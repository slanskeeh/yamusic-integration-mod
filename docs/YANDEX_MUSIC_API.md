# Яндекс Музыка: что удалось установить

Дата проверки: 17 октября 2026. Живой аккаунт в этой среде не использовался: токен и пароль в исходники не кладутся, и у сборки их нет. Ниже — то, что следует из открытой документации и кода клиентов, а не из удачного проигрывания трека.

## Официального API воспроизведения нет

У Яндекса есть общий OAuth Яндекс ID. Отдельного стабильного публичного API, которое отдаёт каталог и аудио Яндекс Музыки стороннему приложению, в открытой документации нет. Своё OAuth-приложение для Музыки зарегистрировать нельзя: клиенты пользуются уже существующим идентификатором официального приложения.

Источник: документация библиотеки MarshalX, раздел получения токена, https://ym.marshal.dev/token/

## Неофициальный контракт

Рабочая база, которой пользуются открытые клиенты: `https://api.music.yandex.net`.

Авторизация: заголовок `Authorization: OAuth <токен>`. Дополнительно библиотека передаёт `X-Yandex-Music-Client: YandexMusicAndroid/24023621`.

Для прототипа взяты только эти методы, по исходникам `yandex-music-api`:

- `GET /account/status` — uid, логин, отображаемое имя.
- `GET /users/{uid}/likes/tracks` — идентификаторы любимых треков. Полный каталог прототип не строит, берётся первый id.
- `POST /tracks` с полем `track-ids` — название, исполнители, `available`, `durationMs`.
- `GET /tracks/{id}/download-info` — старый список вариантов загрузки.

Прямая ссылка для воспроизведения берётся из `GET /get-file-info`: качество `hq`, затем `nq`, кодек только `mp3`, доставка только `raw`. Подпись — HMAC из открытого десктопного клиента, вместе с заголовком `X-Yandex-Music-Client: YandexMusicDesktopAppWindows/5.95.0`. Источник: `yandex_music/utils/sign_request.py` и `yandex_music/_client/tracks.py` в библиотеке MarshalX. Токен на адрес CDN не отправляется. Ключ `encraw` не читается.

Старый XML `download-info` и адрес `/get-mp3/` больше не используются для воспроизведения: такой ответ открывался, но не содержал кадров mp3.

Для коллекции, по тем же исходникам MarshalX, добавлены:

- `GET /search?text=&type=all&page=0` — треки, альбомы, исполнители и плейлисты первой страницы.
- `GET /albums/{id}/with-tracks` — треки альбома.
- `GET /artists/{id}/tracks?page=0&page-size=40` — треки исполнителя.
- `GET /users/{uid}/playlists/list` и `GET /users/{uid}/playlists/{kind}` — плейлисты пользователя.
- `POST /users/{uid}/likes/tracks/add-multiple` и `POST /users/{uid}/likes/tracks/remove` с полем `track-ids`. Успех — только если в `result` есть `revision`.
- `POST /rotor/session/new` с JSON `{"seeds":["user:onyourwave"],"includeTracksInResponse":true}` и `POST /rotor/session/{id}/tracks` для следующей партии. `POST /rotor/session/{id}/feedback` сообщает `radioStarted`, `trackStarted`, `trackFinished` или `skip`. В теле есть `batchId`, если станция его прислала. Пропуск или конец трека уходит до запроса следующей партии.
- `GET /users/{uid}/likes/albums` — альбомы, отмеченные пользователем.

Подкасты, клипы и изменение состава плейлиста не запрашиваются. Любимые треки загружаются все, метаданные — пачками по 50. Обложка берётся из `coverUri` или `ogImage`, `%%` заменяется на `200x200`, адрес остаётся https-доменом Яндекса.

## Зашифрованная доставка

Новый метод `GET /get-file-info` умеет качества `lossless`, `hq`, `nq` и транспорт `raw` или `encraw`. Для `encraw` файл зашифрован, а открытые клиенты расшифровывают его AES-128-CTR ключом из ответа.

Источники:

- https://ym.marshal.dev/yandex_music.track.file_download_info/
- https://ym.marshal.dev/yandex_music.utils.decrypt/

Прототип этот метод не вызывает и расшифровку не реализует. Если `download-info` тоже пометит вариант как `encraw` или не вернёт обычный mp3, экран покажет отказ.

## Другие ограничения сервиса

По опыту сторонних провайдеров, не по нашему прогону:

- Токен истекает, после этого API отвечает отказом авторизации.
- Часть треков недоступна из-за региона или типа подписки.
- Долгие соединения CDN обрываются. Для длинного файла надёжнее читать его окнами по несколько мегабайт, а не одним бесконечным запросом. В прототипе окна не сделаны: обрыв закрывает сессию.
- Своё OAuth-приложение создать нельзя, поэтому сценарий входа внутри игры хрупкий.

Источник по сроку токена, геоограничениям и обрывам: https://trudenboy.github.io/ma-provider-yandex-music/known-issues/

## Как передать токен в прототип

Не присылайте токен в чат и не вставляйте его в код.

Практический способ из документации библиотеки — OAuth Device Flow: игра запрашивает код у `https://oauth.yandex.ru/device/code`, показывает его и открывает страницу Яндекса. Пароль в игру не вводится. После подтверждения `POST https://oauth.yandex.ru/token` возвращает `access_token`, и он записывается в `config/redio/token.txt`. Выход удаляет этот файл. Переменная `YANDEX_MUSIC_TOKEN` по-прежнему сильнее файла: выход её не стирает.

Запасной путь — вставить в настройки адрес страницы с `access_token` в фрагменте. В код и в чат токен класть не нужно.

## Что проверено запросом без токена

17 октября 2026, `GET https://api.music.yandex.net/account/status` без заголовка авторизации:

- HTTP 200
- в `result.account` есть `region` 225, `regionCode` `ru` и `serviceAvailable: true`
- `uid` и логина нет

Прототип считает такой ответ отказом: аккаунт не подтверждён. Гостевой ответ не используется как успешный вход. Живой токен в этой сборке не проверялся.

## Что это значит для следующих фаз

Фазы 2 и дальше не начинаются, пока на реальном аккаунте не выполнено одно из двух:

1. Прототип внутри клиента воспроизвёл незашифрованный mp3, пауза и стоп освободили звук.
2. Либо зафиксировано, что сервис больше не отдаёт такой поток, и выбран другой допустимый способ.

Варианты, если незашифрованного потока нет:

- Оставить мод на метаданных и локальных файлах, которые пользователь сам указал.
- Искать другой разрешённый источник звука.
- Не начинать расшифровку без отдельного решения: текущая спецификация её запрещает.

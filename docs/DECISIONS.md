# Решения

## Подтверждено

### Forge 1.20.1-47.4.28 и Java 17

Контекст: нужен фиксированный Forge 47.x. На дату 17 октября 2026 сборка 47.4.28 была последней опубликованной для 1.20.1.

Решение: взять официальный MDK `1.20.1-47.4.28`. SHA-1 архива `eee9145e892bb5ca5fe72323bd81c8522c53417f` совпал с сайтом Forge.

Причины: MDK уже содержит Gradle 8.8, ForgeGradle 6 и набор запусков client/server. Версия не плавает между сборками.

Альтернативы: более старая рекомендованная ветка 47.2 или 47.3. Они дальше от текущих исправлений Forge.

Последствия: обновление Forge делается отдельным шагом, а не попутно с функциями.

### Имя мода

Решение: `modid` = `yandexmusic`, пакет `dev.yamod.yandexmusic`, имя «Yandex Music Integration», версия `0.1.0`.

Причины: `modid` короткий и подходит под правила Forge. Пакет совпадает с `group` в Gradle.

### Токен вне исходников

Решение: токен читается из `YANDEX_MUSIC_TOKEN` или из `config/yandexmusic/token.txt`. В конфиг Forge он не кладётся.

Причины: конфиг Forge виден в интерфейсе и легко попадает в копии мира и логи. Пароль аккаунта не используется.

Последствия: файл с токеном лежит открытым текстом на компьютере игрока. Это ещё не защищённое хранилище. Перед релизом его нужно заменить.

### Зашифрованный поток не воспроизводится

Решение: вариант `transport=encraw` отклоняется. Ключ из ответа не читается и не сохраняется. AES-расшифровка не написана.

Причины: спецификация запрещает обход технической защиты. Прототип просит у `get-file-info` только кодек `mp3` и доставку `raw`.

Альтернатива: повторить расшифровку из неофициальных клиентов. Отклонена.

Последствия: если сервис отдаёт только `encraw`, реальное воспроизведение трека недоступно, и следующие фазы не начинаются, пока способ не пересмотрен.

### Своя маленькая HTTP-обёртка вместо готовой библиотеки

Решение: для прототипа написан узкий клиент на `java.net.http.HttpClient`.

Причины: распространённая JVM-библиотека `yandex-music-api-jvm` лицензирована GPL-3.0. Тянуть её в мод нельзя без отдельного решения о лицензии. Своя обёртка покрывает четыре запроса и не притворяется полным API.

Альтернатива: библиотека MarshalX на Python. Она удобна для исследования, но не работает внутри Minecraft.

## Предварительно

### JLayer 1.0.1 для mp3

Контекст: Java Sound не декодирует mp3. Тот же JLayer внутри процесса игры до первого кадра не доходит, хотя вне игры этот файл декодируется.

Решение: зависимость `javazoom:jlayer:1.0.1`, лицензия LGPL, без нативного кода. Декодирование идёт отдельным процессом `java`, classpath — классы мода и `jlayer-1.0.1.jar`. PCM возвращается в игру и играется через OpenAL.

Альтернативы: JavaFX Media плохо стыкуется с Forge. VLC тащит нативные библиотеки. Расшифровка `encraw` не рассматривается.

Последствия: для проверки нужен запуск через `./client.sh`, чтобы класс декодера лежал каталогом, а не внутри собранного jar. Перемотки нет.

### Звук через OpenAL Minecraft

Контекст: первая версия прототипа играла через Java Sound. Это отдельное устройство, поэтому трек мог «запускаться» в тишине, пока музыка Minecraft была слышна.

Решение: незашифрованный mp3 декодируется JLayer и отдаётся потоковому каналу OpenAL той же игры. Пока сессия играет или стоит на паузе, `MusicManager` останавливает текущую музыку и не запускает следующую. Громкость берётся из общей громкости Minecraft; если она почти выключена, прототип играет на полной, чтобы проверку было слышно.

Причины: звук должен идти в то же устройство, что и игра. Расшифровка `encraw` по-прежнему не делается.

Последствия: прототипу нужен access transformer на `SoundManager.soundEngine`, `SoundEngine.channelAccess` и `MusicManager.nextSongDelay`. Классы Java Sound в проекте больше не используются экраном.

### Неофициальный API

Решение: прототип ходит в `https://api.music.yandex.net` так, как это описано в открытой библиотеке MarshalX. Официального публичного API воспроизведения нет.

Последствия: контракт может сломаться без предупреждения. `get-file-info` вызывается только с `codecs=mp3` и `transports=raw`. Поле ключа и доставка `encraw` не используются.

Подробности и источники: `docs/YANDEX_MUSIC_API.md`.

### Репозитории Gradle указаны явно

Контекст: первая сборка падала в шаге `listLibraries` с текстом `no repositories are defined` для `com.mojang:blocklist:1.0.10`. Загрузчик ForgeGradle не видел свои же Maven-репозитории в запасном пути.

Решение: в `build.gradle` явно добавлены Maven Central, `libraries.minecraft.net` и `maven.minecraftforge.net`. Таймаут загрузки Gradle Wrapper увеличен до 120 секунд: на 10 секундах архив Gradle обрывался.

Причины: без этого официальный MDK на этой машине не доходил до компиляции.

Последствия: список репозиториев дублирует то, что ForgeGradle и так пытается добавить. Это зафиксированная обходная мера, а не новая библиотека.
